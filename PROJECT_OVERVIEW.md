# Learnify — Project Overview

Crisp reference for what this project actually is and what every file does. For *why* decisions were made, see `BACKEND_PLAN.md` and `design/`; for build order, see `IMPLEMENTATION_PLAN.md`.

---

## 1. What We Created

**The product:** type a topic → get a full structured course (3–6 modules, 3–5 lessons each) with objectives, worked examples, embedded YouTube videos, MCQ quizzes, optional Hinglish audio narration, and PDF export — generated by Gemini, persisted, and viewable in a real web app.

### Backend (Spring Boot, Java) — `server/`

- **Auth (real, not stubbed).** Every `/api/v1/**` route requires a valid Auth0 JWT. Identity is resolved *only* from the verified token — never a client-supplied param — so ownership can't be spoofed. A course/module/lesson belonging to another user returns `404`, not `403` (doesn't even confirm the ID exists).
- **Persistence.** `User → Course → Module → Lesson`, on PostgreSQL. Lesson content is an open JSON array (`heading`/`paragraph`/`code`/`video`/`mcq` blocks) — new block types are additive, no migration needed.
- **The generation pipeline — the actual core.** `POST /courses/generate` doesn't call the AI synchronously; it creates a `PipelineRun` and a chain of `JobStep`s (`OUTLINE` → `LESSON_CONTENT` × N → `ENRICHMENT` × N), which a background poller works through, persisting results at each step. The frontend polls `GET /jobs/{id}/status` for live progress (current step, queue position) until it flips to `DONE`. A malformed AI response retries automatically (feeding the error back into the next prompt attempt) before failing cleanly after 3 tries.
- **AI content generation.** Prompts are external JSON templates, not inline strings, and deliberately structured as History → full A–Z teaching content with examples → Real-World Application → 4–5 MCQs — aimed at genuine understanding, not filler.
- **BYO API keys.** A user can store their own Gemini key (AES-encrypted at rest); if it fails mid-generation, the pipeline automatically falls back to the default project key and flags it back to the frontend (`usingDefaultKey`), rather than either silently substituting or hard-failing.
- **Rate limiting.** Sliding-window log (max 2 generation requests per 60s per user), plain SQL, no external cache needed.
- **YouTube enrichment.** Each lesson's AI-generated video *search query* gets resolved to a real embeddable video ID during the `ENRICHMENT` step.
- **Hinglish audio (on-demand).** A per-lesson endpoint translates the lesson's text to Hinglish and synthesizes speech via Gemini TTS, returning a playable WAV. This is the one integration not verified against the live API (no key available yet) — everything around it (translation prompt, WAV framing, auth/ownership, the endpoint itself) is tested; the raw Gemini TTS request/response contract is the one thing to sanity-check first once a real key exists.
- **Admin view.** A small allowlisted-user dashboard (recent jobs, failures, counts) reading the same tables the pipeline already writes to — no separate monitoring stack.
- **Course export.** Full course/module/lesson tree as one JSON document.

### Frontend (React + TypeScript + Tailwind) — `client/`

- **Full auth-gated app**: logged-out landing page → prompt form + your course list → live generation progress → course overview → lesson viewer with sidebar navigation, prev/next, objectives.
- **Real interactivity**: clickable MCQs with instant right/wrong feedback, copy-to-clipboard code blocks, real YouTube embeds, a Hinglish "listen" button that fetches and plays audio, one-click PDF export (captures a hidden, forced-light-theme render of the lesson regardless of the viewer's dark-mode setting), one-click JSON export, and a Settings page to manage your own API key.
- **Design system**: CSS custom properties for a full light/dark palette (indigo primary, slate neutrals), toggle persisted to `localStorage`, consistent card/spacing language throughout — not default/unstyled HTML.

### What's deliberately not built

- Course **import** (only export) — explicit future scope.
- Webhook/event system — explicit future scope.
- Production-grade secret storage (KMS/vault) in place of AES-at-rest — explicit future scope, noted in code.
- Actual deployment (Render/Vercel accounts, live URLs) and the demo video/README polish — these are manual/process steps (Phase 11–12), not code.

## 2. File Reference

### Backend — `server/src/main/java/com/learnify/`

**`LearnifyApplication.java`** — entry point; `@EnableScheduling` turns on the pipeline poller.

**`config/`**
| File | Purpose |
|---|---|
| `SecurityConfig.java` | Builds the JWT decoder (issuer/audience validation against Auth0) and the security filter chain (`/actuator`, `/swagger-ui` public; everything else authenticated). |

**`entity/`** — JPA entities, one per DB table.
| File | Purpose |
|---|---|
| `User.java` | Auth0-linked user (`auth0Sub`, `email`). |
| `Course.java` | Title/description/tags/`ownerId`. |
| `Module.java` | Belongs to a `Course`, ordered. |
| `Lesson.java` | Belongs to a `Module`; `content` is the open JSONB block array; `objectives`; `isEnriched`. |
| `PipelineRun.java` | One course-generation request: owner, resulting course, overall status. |
| `JobStep.java` | One pipeline step: type, status, `dependsOnStepId`, `input`/`output` JSONB, retry `attempt`, `error`. |
| `GenerationRequestLog.java` | One row per generation attempt — rate-limit audit trail. |
| `UserApiKey.java` | A user's encrypted BYO Gemini key. |

**`repository/`** — Spring Data interfaces (one per entity above); the only place raw queries live. Notable custom queries: `JobStepRepository.findRunnableSteps()` (dependency-aware "what can run next"), owner-scoped finders (`findByIdAndOwnerId`, `findByIdAndCourse_OwnerId`, `findByIdAndModule_Course_OwnerId`) that make ownership enforcement structural, not optional.

**`security/`**
| File | Purpose |
|---|---|
| `CurrentUserProvider.java` | Interface: "who's making this request" — the seam that makes auth swappable. |
| `JwtCurrentUserProvider.java` | Active implementation: resolves the user from the verified JWT. |
| `DefaultCurrentUserProvider.java` | Inactive (no `@Component`) single-user stand-in, kept to prove the seam works. |
| `AuthenticatedUserResolver.java` | Finds-or-creates the internal `User` row from a JWT's `sub`/`email`. |
| `AudienceValidator.java` | Extra JWT validator checking the `aud` claim matches our API. |

**`ai/`** — course/lesson generation core.
| File | Purpose |
|---|---|
| `GeminiClient.java` | Thin HTTP wrapper calling Gemini's `generateContent`, extracting the text response. |
| `JsonResponseValidator.java` | Parses raw AI output (stripping stray markdown fences), validates required fields, enforces `BlockType` on every content block. |
| `BlockType.java` | The registry of valid lesson block types (`heading`/`paragraph`/`code`/`video`/`mcq`). |
| `GeneratedCourse.java` / `GeneratedModule.java` / `GeneratedLesson.java` | Plain records for validated AI output. |
| `AiGenerationException.java` | Thrown on any AI-call or validation failure; caught by `RetryPolicy`. |
| `prompt/PromptTemplate.java` | Record: `{system, template}`. |
| `prompt/PromptTemplateLoader.java` | Loads a template JSON file off the classpath. |
| `prompt/CoursePromptBuilder.java` / `LessonPromptBuilder.java` | Fill a template's placeholders (and an optional retry-error hint) into a final prompt string. |

**`pipeline/`** — the async job queue.
| File | Purpose |
|---|---|
| `JobStatus.java` / `JobStepType.java` | Enums: `PENDING/RUNNING/DONE/FAILED`, `OUTLINE/LESSON_CONTENT/ENRICHMENT`. |
| `OutlineFunction.java` | Pure `Function<Input,Output>`: topic → validated `GeneratedCourse`. |
| `LessonContentFunction.java` | Pure `Function`: course/module/lesson titles → validated `GeneratedLesson`. |
| `EnrichmentFunction.java` | Pure `Function`: video search query → YouTube video ID. |
| `PipelineOrchestrator.java` | Rate-limits, then creates a `PipelineRun` + first `OUTLINE` step. |
| `PipelinePoller.java` | `@Scheduled` loop; finds runnable steps, hands each to `JobStepProcessor`. |
| `JobStepProcessor.java` | The actual step logic: calls the right `Function`, resolves/falls-back the API key, persists Course/Module/Lesson rows, enqueues the next step, marks the run `DONE`. This is where most of the real orchestration logic lives. |
| `RetryPolicy.java` | On failure: re-enqueue with the error fed back into the next attempt, up to 3 tries, then mark `FAILED`. |

**`integration/youtube/`**
| File | Purpose |
|---|---|
| `YouTubeClient.java` | Calls YouTube Data API v3 search; returns a video ID or nothing (never throws — a failed lookup shouldn't fail the lesson). |

**`integration/gemini/`**
| File | Purpose |
|---|---|
| `TranslationClient.java` | Reuses `GeminiClient` with a Hinglish-translation prompt. |
| `GeminiTtsClient.java` | Calls a Gemini TTS model, decodes the returned audio. **Unverified against the live API** — see §1. |
| `WavEncoder.java` | Wraps raw PCM bytes in a standard WAV header so browsers can play it. Fully unit-tested, no network involved. |

**`apikey/`**
| File | Purpose |
|---|---|
| `ApiKeyEncryptor.java` | AES-GCM encrypt/decrypt for stored user keys. |
| `ApiKeyResolver.java` | Given a user, returns their key (decrypted) or the default, tagging which source it used. |

**`ratelimit/`**
| File | Purpose |
|---|---|
| `SlidingWindowRateLimiter.java` | Checks + records a generation attempt against the 60s/2-request window. |
| `RateLimitExceededException.java` | → `429`. |

**`admin/`**
| File | Purpose |
|---|---|
| `AdminAuthorizer.java` | Checks a JWT `sub` against a configured allowlist. |
| `AdminAccessDeniedException.java` | → `403`. |

**`controller/`** — REST endpoints, thin (delegate to services).
| File | Endpoints |
|---|---|
| `CourseController.java` | Create/get/list courses; `GET /{id}/export`. |
| `ModuleController.java` | Create/list modules under a course. |
| `LessonController.java` | Create/list lessons under a module; `GET /{lessonId}/audio` (Hinglish TTS). |
| `JobController.java` | `POST /courses/generate`, `GET /jobs/{id}/status`. |
| `ApiKeyController.java` | GET/PUT/DELETE the current user's stored API key. |
| `AdminController.java` | `/admin/jobs`, `/admin/errors`, `/admin/stats`. |

**`service/`** — business logic between controllers and repositories.
| File | Purpose |
|---|---|
| `CourseService.java` / `ModuleService.java` / `LessonService.java` | CRUD + owner-scoped fetch-or-404 for each entity. |
| `CourseExportService.java` | Assembles the full course/module/lesson tree into the export DTO. |
| `LessonAudioService.java` | Orchestrates translate-then-synthesize for the Hinglish audio endpoint. |

**`dto/request/` & `dto/response/`** — one record per API input/output shape; controllers never expose entities directly over the wire.

**`exception/`**
| File | Purpose |
|---|---|
| `NotFoundException.java` | → `404`. |
| `GlobalExceptionHandler.java` | Central `@RestControllerAdvice` mapping every domain exception to a consistent JSON error body + status. |

**`resources/`**
| File | Purpose |
|---|---|
| `application.yml` | All configuration, every value overridable by an env var with a safe local default. |
| `db/migration/V1–V4__*.sql` | Flyway migrations, in order: baseline check, domain model, pipeline tables, rate-limit/API-key tables. |
| `prompts/course-prompt.json` / `lesson-prompt.json` | The actual AI prompt templates — externalized so they're editable without a code change. |

**`src/test/java/...`** mirrors the structure above — one test class per component, using Testcontainers (real Postgres) + mocked external clients (`GeminiClient`, `YouTubeClient`, `TranslationClient`, `GeminiTtsClient`) so no test ever makes a real network call.

### Frontend — `client/src/`

**`main.tsx`** — mounts the app inside `Auth0Provider` + `BrowserRouter`.
**`App.tsx`** — auth gate (loading/landing/app) + all route definitions.
**`index.css`** — the entire design system: light/dark color tokens as CSS custom properties, fonts, base styles.
**`vite-env.d.ts`** — typed `import.meta.env` for the `VITE_*` variables.

**`pages/`**
| File | Purpose |
|---|---|
| `Landing.tsx` | Logged-out hero + "Log in" button. |
| `Home.tsx` | Prompt form, live generation progress, list of your courses. |
| `CoursePage.tsx` | Course header + modules/lessons overview + JSON export button. |
| `LessonPage.tsx` | Sidebar nav, objectives, rendered content, PDF export, Hinglish audio, prev/next. |
| `SettingsPage.tsx` | View/set/clear your own Gemini API key. |
| `AdminPage.tsx` | Stats/jobs/errors dashboard; shows a 403 message gracefully for non-admins. |

**`components/`**
| File | Purpose |
|---|---|
| `Navbar.tsx` | Top bar: logo, Settings/Admin links, dark-mode toggle, user avatar/logout. |
| `PromptForm.tsx` | Topic input + example-topic quick-fill chips. |
| `GenerationProgress.tsx` | Live status card (current step, queue position, key-fallback notice). |
| `CourseCard.tsx` | One course tile in the Home list. |
| `SidebarNavigation.tsx` | Module/lesson tree nav, highlights the active lesson. |
| `LessonRenderer.tsx` | Dispatches each content block to its matching component by `type`. |
| `ExportCourseButton.tsx` | Fetches the export JSON and triggers a browser download. |
| `LessonPDFExporter.tsx` | Renders an off-screen, forced-light-theme copy of the lesson and captures it to a paginated PDF (`html2canvas` + `jsPDF`). |
| `HinglishAudioButton.tsx` | Fetches the lesson's Hinglish audio as a blob and plays it. |
| `LoadingSpinner.tsx` / `ErrorMessage.tsx` | Shared status/error UI. |

**`components/blocks/`** — one component per `BlockType`, matching the backend registry exactly.
| File | Purpose |
|---|---|
| `HeadingBlock.tsx` / `ParagraphBlock.tsx` | Plain text rendering. |
| `CodeBlock.tsx` | Monospace block with a copy-to-clipboard button. |
| `VideoBlock.tsx` | Real YouTube iframe if enriched, otherwise shows the search query. |
| `MCQBlock.tsx` | Clickable options, instant correct/incorrect coloring + explanation. |

**`hooks/`**
| File | Purpose |
|---|---|
| `useApi.ts` | Auth-aware fetch wrapper (`get`/`post`/`put`/`del`/`getBlob`), throws `ApiError` on non-2xx. |
| `useJobPolling.ts` | Polls `GET /jobs/{id}/status` every 2s until `DONE`/`FAILED`. |
| `useCourseTree.ts` | Fetches a course + its modules + lessons as one tree; shared by `CoursePage` and `LessonPage`. |
| `useDarkMode.ts` | Reads/toggles/persists the light-dark preference. |

**`utils/`**
| File | Purpose |
|---|---|
| `api.ts` | `API_BASE_URL` constant + `ApiError` class. |
| `api-types.ts` | Hand-written TypeScript types matching every backend DTO exactly (see the note in §1 — not auto-generated from `openapi.yaml`). |

**`*.test.tsx`** — `App.test.tsx` (landing page renders logged-out), `PromptForm.test.tsx`, `MCQBlock.test.tsx`, `CodeBlock.test.tsx` (interactivity, not just rendering).
